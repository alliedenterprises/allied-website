# SEO Audit — Next.js build, all pages

**Date:** 9 November 2026
**Scope:** Every page in the new Next.js site, all old WordPress URLs, and sitewide technical SEO.
**Status:** Most recommendations were implemented the same day. See **§8** for what was done, how it was verified, and what remains.
**Follows:** `docs/seo-audit.md` (27 October 2026), which covered the old WordPress site, competitors and the keyword map. That audit still applies. This one checks the build against it.

---

## 0. Method and limits

**What was done**

- Crawled all **32 sitemap URLs** on the local dev server with **JavaScript disabled**, so each page was read as a crawler first receives it.
- On every page, checked the following:
  - status code;
  - title, meta description, canonical and meta robots;
  - Open Graph and Twitter tags;
  - H1s and heading order;
  - word count of the main content;
  - image `alt` attributes;
  - JSON-LD, which was parsed to confirm it is valid;
  - every link.
- Requested every **internal link target** (33 URLs) and every **old WordPress URL** in `docs/url-inventory.md` (43 URLs) without following redirects.
- Ran technical checks:
  - `robots.txt`, sitemap and favicon;
  - the 404 page;
  - URLs without a trailing slash, in upper case, and with a query string;
  - `/admin/` and `/api/`.
- Searched all content files for unverified superlatives and claims.

**What was not available, so nothing below is based on it**

- **Google Search Console:** no data on impressions, clicks, indexing or backlinks.
- **Keyword tool:** no search volume or difficulty figures.
- **Core Web Vitals:** not measured. The dev server is not representative. Run PageSpeed Insights on the production deployment.
- **Production hosting:** the live domain still serves WordPress. Redirect behaviour, HTTPS and the `www` setup must be re-checked after launch.

## 2. Launch blockers (P0)

CLAUDE.md §14A forbids switching the domain until these pass.

### 2.1 Eleven old WordPress URLs return 404

| Old URL | Suggested action (**needs human approval**) |
|---|---|
| `/products/` | Build the product catalogue (see §4.6). Until then, a 301 to `/zkteco-qatar/` is the closest match |
| `/vision/` | 301 → `/about-us/` (it has a "Vision" section) |
| `/quality-policy/` | 301 → `/about-us/` (it has a "Quality Policy" section) |
| `/team-allied/` | 301 → `/about-us/` (it has an "Our team" section) |
| `/support/` | 301 → `/contact-us/` |
| `/downloads/` | Check what it held (datasheets? BioTime installers?). Rebuild it if it gets traffic, otherwise 301 → `/contact-us/` |
| `/blog/`, `/hello-world/`, `/project/`, `/category/uncategorized/`, `/author/admin/` | WordPress boilerplate. If Search Console shows no traffic or links, let them 404 (or return 410). **Do not** send them to the homepage |

Add the approved redirects to `next.config.ts` (`redirects()` does not exist yet), then update `docs/url-inventory.md` in the same change.

### 2.2 WordPress media and PDF URLs are not inventoried

`/wp-content/uploads/…` files (datasheets, images) may have backlinks or image-search traffic. Export them from Search Console or a backlink tool before launch.

### 2.3 There is no `robots.txt`

`/robots.txt` returns 404. Add `src/app/(frontend)/robots.ts` with the following:

- `Allow: /`
- `Disallow: /admin/` and `Disallow: /api/`
- `Sitemap: https://alliedeprs.com/sitemap.xml`

**Preview deployments:** the site is also deployed at `allied-web-ten.vercel.app`. Canonicals point to alliedeprs.com, which limits the damage. Even so, any non-production host should send `noindex`, for example a `robots.ts` or `X-Robots-Tag` header that switches on an environment variable. That keeps preview copies out of Google.

## 3. Technical SEO (P1)

1. **No Open Graph or Twitter metadata on any page.**
   - Links shared on WhatsApp, LinkedIn or X show no image and a generic preview. WhatsApp is a main enquiry channel here.
   - Add `openGraph` defaults in the root layout: `siteName`, `type: 'website'`, `locale`, and a default 1200×630 image (or an `opengraph-image` file).
   - Each page then needs its own `og:title`, `og:description` and `og:url`. A small helper that builds `title`, `description`, `canonical` and `openGraph` from one object would keep all 32 pages consistent.
2. **No favicon or app icon.**
   - Google shows the favicon next to results on mobile. Without one, the result shows a generic globe.
   - Add `src/app/icon.png` (or `favicon.ico`) and `apple-icon.png`, based on the Allied logo mark.
3. **The 404 page is a dead end.**
   - Unknown URLs get the default "404: This page could not be found." with no header, footer or navigation.
   - Add a branded not-found page with the site layout, links to the main sections, and the contact CTA.
   - Keep it returning a real 404 status. It already does, with `noindex`.
4. **Breadcrumbs are missing on 26 pages.**
   - BreadcrumbList JSON-LD is only on the 4 hub pages and `/contact-us/`.
   - Service pages have neither a visible breadcrumb nor the structured data, for example Home › Time Management › Time Attendance System.
   - Add both. Breadcrumbs in results also show the site structure.
5. **LocalBusiness JSON-LD can be more complete.** All of these use data that is already verified in `company.ts`:
   - Add `geo` (`lat`/`lng` are already in `company.ts`).
   - Add `hasMap` (the Google Maps listing URL).
   - Use a real photo for `image` instead of the logo.
   - Consider a more specific type that matches the Google Business Profile category, for example `ElectronicsStore`. **Confirm the category first.**
6. **On the homepage, the hero headings come before the H1.** The five banner slides use `<h2>`, and the page's H1 ("Leading Supplier…") sits below the banner. The outline therefore starts with five H2s. Either make the hero's main line the H1, or make the slide titles non-heading text. See also §4.1.
7. **Minor:**
   - **Long titles:** these may be truncated in results: home (69 characters), GIS (66), gate barrier (65), ERP (64).
   - **Unused title template:** the root layout's `title.template` ("%s | Allied Enterprises Qatar") is unused, because every page sets an absolute title. Align it with the "| Allied Enterprises" pattern so any future page is correct by default.

## 4. Content, keywords and internal linking (P1–P2)

### 4.1 Homepage H1 and intro use unverified superlatives

- **H1:** "Leading Supplier for Time Attendance Systems in Qatar – Biometric Supplier in Qatar". This repeats "in Qatar" and claims "leading".
- **Intro:** "known for our time attendance system Qatar … the leading biometric attendance machine supplier … the best biometric fingerprint scanner price in Qatar". It is ungrammatical and makes unverifiable claims, which conflicts with CLAUDE.md §5.
- **Suggestion:** use the CLAUDE.md §7 draft H1, "ZKTeco Supplier in Qatar for Biometric Attendance & Access Control", and rewrite the intro factually: authorized ZKTeco status, 3000+ installations as of 2026, two Doha offices, and supply, install and support.
- **Approval:** this paragraph was the company's own requested wording, so it needs their approval.

### 4.2 Superlative claims elsewhere (replace with facts, or verify)

| File | Claim |
|---|---|
| `access-control.ts` | "Leading access control system provider in Qatar"; "best access control systems supplier in Qatar"; "Delivering the Best Access Control Solutions…" |
| `time-attendance.ts` | Eyebrow: "Qatar's leading supplier for time attendance systems" |
| `about.ts` / `company.ts` | "one of the leading professional vendors"; "the best hands in the industry"; "expertise guarantees…" |
| `pabx.ts` | "the best telephone systems in Qatar"; "one of the best telephone solution companies" |
| `structured-cabling.ts` | "Choose the Best Data Cabling Company in Qatar"; "guarantee consistent and clear communication" |
| `public-address.ts` | "As a leading public address system installer" |
| `gate-barrier.ts` | "a recognised distributor, dealer and supplier" (fine if the certificate supports it; see 4.3) |

### 4.3 ZKTeco status wording is inconsistent

| Where | Wording used |
|---|---|
| Homepage certificate | "Authorized ZKTeco **Distributor**, Qatar · 2026" (from the 2026 ZKTeco certificate) |
| `/zkteco-qatar/` | "authorized ZKTeco **dealer**/**agent**". `zkteco.ts` deliberately avoids "distributor" because, when the page was written, nothing confirmed it |
| `/about-us/` | "Authorized ZKTeco **agent**" |

The certificate now provides that evidence, so:

- Confirm the role with the company, then use the same wording everywhere.
- Show the certificate on `/zkteco-qatar/`, the page that targets "ZKTeco supplier / dealer / authorized dealer Qatar". It is the strongest trust signal for that page.

### 4.4 `/about-us/` competes with `/zkteco-qatar/`

- **The overlap:** the About page's title "About Allied Enterprises | Authorized ZKTeco Agent in Qatar" and its H2 "Authorized ZKTeco agent in Qatar" target the same intent as `/zkteco-qatar/`. The October audit recommended a brand-focused About title once `/zkteco-qatar/` existed.
- **The fix:** retitle the About page around the company, for example "About Allied Enterprises | IT & Security Solutions in Doha", and link its ZKTeco section to `/zkteco-qatar/`.
- **The homepage title:** it also leads with "ZKTeco". That is acceptable for the broad company query, but watch for cannibalization in Search Console.

### 4.5 Internal linking: weak links to the key ZKTeco page

These are links from the main content of other pages, not the menu or footer:

| Page | Contextual links in | Comment |
|---|---|---|
| `/zkteco-qatar/` | **1** | **Priority-A page, under-linked.** Link it from the homepage intro, time attendance, access control, BioTime, gate barrier and About pages |
| `/about-us/` | 0 | Reachable only from the menu and footer |
| Hub pages (`/time-management/`, `/it-infrastructure-qatar/`, `/applications/`, `/solutions/`) | 0 | Acceptable (menu hubs), but service pages could link up to their hub |
| `/time-attendance-system-qatar/` | 11 | Good |
| `/access-control-system-qatar/` | 10 | Good |
| `/contact-us/` | 31 | Good (CTAs) |

All pages are reachable through the menu and footer, so there are no orphans.

### 4.6 Content gaps for priority keywords

1. **Product catalogue.**
   - There is **no Payload `products` collection**, even though CLAUDE.md §13 describes one.
   - `/products/` is an old URL that now 404s.
   - Model pages (specs, datasheets) are the biggest gap found in the October competitor research. No Qatar competitor has them, and marketplaces win model searches.
   - Build `/products/` and `/products/[slug]/` with `Product` JSON-LD. Do not include prices, ratings or availability unless they are real.
   - **Needs:** the list of models Allied supplies, and datasheets.
2. **BioTime page is thin.**
   - `/biotime-time-attendance-system-qatar/` has about **293 words**, yet it targets the priority-B query "ZKTeco BioTime software Qatar".
   - Add the following:
     - the 9.5 version details;
     - on-premise vs BioTime Cloud;
     - licensing and device-count guidance;
     - payroll and WPS export;
     - FAQs;
     - a link to the official BioTime 9.5 page.
3. **Other thin pages:** payroll integration (about 241 words) and queue management (about 263 words). Expand them, or keep them as they are until Search Console shows demand.
4. **Price-intent query.** For "biometric attendance system price Qatar", a section on what affects the price fits the time attendance page:
   - device type;
   - number of users and doors;
   - software;
   - installation.

   Do not publish made-up prices.

### 4.7 Copy derived from other sources (duplicate-content risk)

These pages were flagged in `url-inventory.md` as closely following third-party text. Rewrite them with original content when time allows:

- access control (Boon Edam articles);
- fiber optic testing (Wikipedia's OTDR article);
- business process management (a BPM vendor's article);
- business intelligence (a 2019 press release).

### 4.8 Claims that need confirmation

- **"Strategic Partners" logos** (homepage strip): Zebra, Honeywell, Newland, Teltonika, Armatura, Hashmato, Zyxel, Wialon. Confirm each relationship.
- **Client logos** ("Trusted by leading organizations"): confirm Allied has permission to show each one.
- **Google rating** ("4.9 · 236 reviews", as of October 2026): update it regularly. Correctly, no `AggregateRating` schema is used.
- **ISO 9001:2015 / "Free Trial With Support" badge:** confirm both are current (a VERIFY note is already in `home.ts`).

## 5. What passes (keep as is)

- One H1 per page; unique titles and descriptions; correct canonicals with trailing slashes.
- `trailingSlash: true` keeps every old URL path. URLs without the slash 308 to the correct one.
- All 28 rebuilt old URLs and 4 new pages return 200. There are 0 broken internal links and 0 redirect chains.
- Content is server-rendered (React Server Components). Nothing important depends on JavaScript.
- The sitemap lists exactly the 32 live canonical pages.
- Sitewide WebSite + LocalBusiness JSON-LD has both offices, opening hours, contact point and social profiles. NAP (name, address, phone) comes from one source, `company.ts`.
- No fake reviews, ratings or prices in structured data. FAQ schema is deliberately not used.
- Images use `next/image` with dimensions or `fill`. Decorative images use empty `alt`.
- `/admin/` is `noindex, nofollow`.
